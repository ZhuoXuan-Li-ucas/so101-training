# SO-101／ACT 从零搭建提示词

本套提示词用于让 AI 从空工作区编写脚本，完成“校准机械臂 → 添加摄像头 → 遥操作尝试 → 数据采集与制作 → ACT 训练 → 部署验证”。重点保留两套操作习惯：采集窗口中的 S/N/R/V 按键，以及终端 Enter 控制的多轮推理与实时相机预览。

以下脚本名称和接口是交给 AI 的实现要求，不代表目标工作区已经存在这些文件。AI 应根据选定的 LeRobot 版本编写并验证入口，模型、数据集和设备驱动尽量采用该版本的官方实现。

## 1. 先让 AI 理解我的操作习惯

### 数据采集

从终端启动程序，打开 top 和 wrist 两路画面；我在采集窗口操作按键，控制什么时候开始、保存、作废和复位。程序保存我确认成功的演示，自动复位后等待我整理场景，再由我开始下一条。

| 操作 | 希望程序完成的动作 |
| --- | --- |
| 启动 | 显示当前配置和双相机画面，进入准备状态，不自动录制 |
| S | 开始主从臂跟随并录制当前演示 |
| N | 确认本条成功，保存一次，再自动复位 |
| R | 当前未保存片段作废，再自动复位；不删除已保存演示 |
| V | 第一条保存并复位后，确认视频和数据复查完成 |
| M | 在定义好的手动整理／暂停状态恢复跟随，不自动开始录制 |
| Q / Esc | 退出并清理设备与数据写入资源 |

采集界面显示两路画面、当前状态、已保存条数、当前帧数／时长和按键提示。演示不必录满时限，自动复位和场景整理不进入训练数据。达到单条时限后等待我按 N 或 R，不自动把这条演示算成功。

### 实机推理验证

我在终端输入命令，之后所有实验控制都在同一个终端完成；相机窗口用来观察当前夹爪和场景。

```text
启动程序，等待
  → Enter：加载模型、连接从臂和相机，回到保存的 home
  → Enter：开始本轮推理，同时保存动作和双路录像
  → Enter：结束本轮，再回 home
  → 等待 10 秒，我整理场景并手工记录结果
  → 等待新的 Enter，开始下一轮
```

每轮最长 120 秒，可提前结束；默认计划 10 轮，轮数可配置。程序编号、计时并保存所有轮次，成功／失败由我另外记录。推理、复位、等待整理场景时都能看相机。最后一轮结束后复位并退出。`q + Enter` 或 Ctrl+C 用于直接退出，不再追加回位动作。

**输入位置要明确：采集按键在采集窗口；推理 Enter 在启动程序的终端。** 推理相机窗口关闭只关闭显示，不等于停止机械臂。程序应在终端持续提示当前阶段和可用操作。

## 2. 使用方法和阶段划分

第一次先发送 P0 建立工作区，再依次发送 P1–P6。每个阶段先把脚本、配置和离线验证做完；需要现场校准、运动、录制或长时间训练／评估时，审核本次具体命令后执行。已经完成的阶段以文件和运行结果交接，不靠聊天记录猜测。

| 提示词 | 阶段 | 要得到的成果 |
| --- | --- | --- |
| P0 | 建立工作区 | 独立环境、源码版本、目录、配置约定和进度记录 |
| P1 | 校准机械臂 | 设备绑定、校准入口、校准结果和只读核验 |
| P2 | 添加摄像头 | top/wrist 配置、独立预览、可共享的相机缓存 |
| P3 | 遥操作尝试 | 主从映射、实时跟随、home 采样和复位 |
| P4 | 数据采集与制作 | 符合上述按键习惯的采集器、审核、合并与划分 |
| P5 | ACT 训练 | 样本预检、训练入口、完整验证和候选模型 |
| P6 | 部署验证 | 终端 Enter 循环、实时预览、逐轮录像和动作分析 |

其中 P4 和 P6 是主要交互需求，可以直接复制给 AI。新窗口接手时，同时提供项目的 `docs/progress.md` 和实际配置路径。

## 7. P4：按我的习惯编写数据采集脚本

这一段是采集器的核心任务书。即使没有旧项目代码，AI 也应能据此实现相同的操作流程。

```text
请实际编写数据采集与制作脚本。复用本项目已验证的机械臂、相机、主从映射和 home，
以当前 LeRobot 数据集写入接口保存标准数据，保持下面的交互习惯。

一、入口和界面
1. 从终端启动 scripts/record.py，支持 --config、--check、批次名称和本批目标条数。
2. 启动后打开 top/wrist 双画面控制窗口，显示准备/录制/保存/复位/复查等状态。
3. 显示已保存条数、当前帧数/时长、必要的主臂目标与从臂反馈，以及当前可用按键。
4. 采集快捷键在该窗口生效，界面明确提示焦点位置；终端保留日志和 Ctrl+C 退出。
5. 新批次使用新目录；不覆盖、不自动续写旧数据、不自动上传。

二、我实际操作的顺序
1. 两臂回到确认的home，摆好物体，按 S 才开始跟随和录制。
2. 成功后按 N：停止记录新帧，保存这条演示，完成后自动复位两臂。
3. 失败后按 R：作废当前未保存片段，再自动复位；已保存的演示保持不变。
4. 复位后等待我整理场景，必须重新按 S，不能自动开始下一条。
5. 第一条保存并复位后进入 FIRST_REVIEW，展示检查结果/视频位置，按 V 才继续。
6. 每条默认最长120秒，达到时限停止录帧并等待 N 或 R，不自动判断成功。
7. M 只用于已经定义的手动整理/恢复状态，不自动恢复录制。
8. Q/Esc、关闭采集控制窗口或终端 Ctrl+C：结束采集并清理。
   未提交片段不算成功；已提交的保存任务完成一次或明确记录错误。

三、每一帧保存什么
- observation.state：本周期发送动作前读取的从臂实际位置。
- action：主臂经过映射后、本周期真正发送的从臂目标，采用从臂坐标。
- observation.images.top/wrist：本周期取得的RGB图像。
- episode_index、frame_index、全局index、timestamp和任务信息。
统一六维关节顺序和单位，记录 action 与 observation.state 的区别。
夹持时目标与反馈可以不同；不把实际夹爪位置覆盖为动作标签，也不捏造力/扭矩标签。
仅 RECORDING 阶段写训练帧，自动复位、等待、场景整理和纯遥操不进入训练数据。

四、代码结构和异常处理
拆分硬件读写、采集状态机、相机预览、数据写入，避免做成一个难以测试的大循环。
使用单独写入线程串行处理 add/save/discard/finalize，控制线程不等待视频编码。
保存与复位分别管理：提交保存只结算一次，复位异常不能导致重复保存或重复计数。
缓存满或写入失败需要明确报错，不能静默丢帧还宣布数据有效。
复位故障停止继续发送旧轨迹，保留已保存数据及日志；恢复后需要新的显式操作。
忙状态按键不排队触发后续运动，不自动重连后恢复旧运动。
保留通信失败、电机真实故障和无效数据的明确处理，不增加未经审核的限幅或夹爪阈值。

五、数据制作
同时编写 scripts/audit_dataset.py 和 scripts/prepare_dataset.py。
audit 核对元数据、Parquet、帧/轨迹索引、维度、有限值和时间戳，完整解码两路视频，
输出帧数与间隔检查、每条首/中/末截图、审核报告；成功质量由我看视频确认。
prepare 从审核通过的批次合并到新目录，保留原文件和来源episode映射。
参数、条数、帧数和路径来自配置/报告，不写死某次实验的数据规模。
增加旁路位置/光照标签表，先保留真实已知标签，缺失值不推断。
按完整轨迹划分训练/验证；需要分位置覆盖时实际接入对应划分清单并核对加载结果。
新训练的状态/动作归一化统计只来自训练轨迹，图像预处理与所选骨干保持一致。

六、交付和验收
先用模拟状态、模拟相机和临时数据目录验证录制→保存→复位→下一条的流程。
验证失败作废不增加成功数、保存后复位失败不重复计数、第一条V复查、退出清理。
验证写入的视频/状态/动作帧数对应、action 是实际发送目标、复位帧不进入数据集。
提供已经实现且验证过参数解析的启动命令、--check命令、按键说明和输出目录。
先准备两条试采集的完整命令和参数审核，完成实录及审核后再安排批量采集。
```

## 8. P5：ACT 训练和完整验证

```text
继续当前项目，对审核通过的数据训练 ACT，并完成所有候选模型的完整验证。
编写训练配置、scripts/check_training.py、训练启动入口及 scripts/evaluate_checkpoints.py。
优先调用选定 LeRobot 版本的官方模型、数据处理器和训练循环。

起始方案：训练100000步，ResNet18，chunk_size=100，batch_size=4，学习率1e-5，
每5000步保存；这些值全部可配置，显存和设备适配后提交实际生效配置。
从真实元数据和划分清单构建样本，不把验证集默认为最后五条。
预检状态、双路图像、动作块与 action_is_pad 的尺寸及有限值。
检查新训练的归一化统计来源；真正加载训练集统计量，避免验证数据进入统计计算。
预训练权重下载到本工作区并核对完整性，记录实际版本和来源。
运行输出目录保持独立，保存模型、训练配置、前后处理器和统计量。

默认 max_eval_samples=0，完整遍历验证集。若训练期另做快速评估，标明采样范围，
最终选型仍对所有候选checkpoint使用同一个完整验证集，不只抽前500帧。
最终评估保留最后不足一个batch的样本，逐轨迹核对帧数，检查遗漏、重复与划分交叉。
使用官方 ACT forward 的评估损失，说明padding、精度和聚合权重。
同时保存逐轨迹结果、完整排名、检查点哈希和最低损失候选。
权重和处理器随模型加载，不在评估旧模型时换一套新统计量。

先完成配置、离线预检和命令审核，再执行训练/完整评估。
给出训练日志、检查点列表、完整验证范围及选择依据。
离线最低损失模型作为部署候选，进入下一阶段后单独做实机验证。
```

## 9. P6：终端运行推理，同时观察相机

这一段是实机验证器的核心任务书。它把终端交互、持续预览、自动复位和实验记录放在同一个会话里。

```text
请为本项目实际编写 scripts/run_trials.py 和配置，让我在终端逐轮运行 ACT，
同时实时观察 top/wrist 相机。采用本项目选定版本的 LeRobot 官方推理路径，
自行编写的部分主要负责终端状态机、复位、预览、录像和动作记录。

一、终端交互必须符合我的习惯
1. 启动命令后先打印实际参数和按键提示，等待第一次 Enter。
   此前不连接机械臂或相机，不使能扭矩、不发送目标。
2. 第一次 Enter：加载模型、连接从臂和双相机，打开实时画面，返回保存的home。
3. 回位后等待；再次 Enter 才开始本轮推理，并开始本轮动作记录和双路录像。
4. 推理中再次 Enter：结束当前轮，随后返回home。
5. 回位后倒计时10秒，我整理场景；倒计时结束后仍等待新的 Enter 才开始下一轮。
6. 单轮最长120秒，到时与本轮结束一样回位；允许我提前结束。
7. 默认计划10轮且可配置，最后一轮结束并复位后退出卸扭，不再开始第11轮。
8. q + Enter 或 Ctrl+C 请求退出并清理，不再追加回位动作。
9. 连接、复位、倒计时期间的Enter不排队，不会之后突然触发新动作。
10. EOF不能被当作Enter；输入线程只设置事件，运动由控制线程统一调用。

二、实时相机显示
1. 明确告诉我：Enter/q 在启动程序的终端操作，相机窗口用于观察。
2. 相机连接后，推理、复位、倒计时和等待下一轮期间都显示当前画面。
3. 预览直接读取推理程序已经连接的相机缓存，不再次占用同一个视频设备。
4. 采集/控制计划30Hz，预览默认15Hz；显示和编码分别运行，不阻塞控制线程。
5. 关闭某个推理预览窗口只关闭显示，不中断策略，也不等于停止机械臂。
6. 显示失败要在终端说明，不能假装仍有实时画面；模型所需相机采集失败则按真实故障处理。
7. 显示缩放/标注使用副本，不改变模型输入。记录帧时间，避免旧图被误认为当前画面。

三、模型、动作与复位
从完整pretrained_model目录加载模型及训练时保存的前后处理器。
初始对照方案保持训练好的chunk_size；先采用n_action_steps=100、30Hz，
不启用temporal ensembling、插值倍率1；如果模型配置不同，先说明并调整实验方案。
每轮开始清空策略动作队列、插值器和上一轮相关状态，不能执行上轮残余动作。
home 使用实验保存的从臂姿态并核对校准身份，不能使用程序启动时随意摆放的位置。
复位使用该版本可验证的官方插值流程；初始方案3秒、50Hz，所有值可配置并展开审核。
不添加额外夹爪闭合阈值、持续夹紧补偿或未经审核的位置限差。
说明官方连接中的PID、模式、扭矩、加速度和保护寄存器写入。
如需处理启动通信ACK错误，只对明确的同值初始化写入做有界处理，不扩大到所有异常。

四、每轮都保存，不筛掉失败视频
会话新建时间戳目录，保存实际展开的配置、checkpoint路径/哈希和运行日志。
每轮保存top/wrist原始视频、逐帧时间戳和视频状态；推理计算较慢时录像仍独立运行。
rounds.csv保存轮号、开始/结束时间、时长和结束原因。
程序不强制询问成功/失败；我在外部手工记录，提供可填写的结果表模板即可。
时长是本轮运行时间，不自动宣称为任务完成耗时。

五、用于解释夹爪行为的动作记录
记录实际被选中执行的动作、所属chunk和块内步号，而不只保存新chunk的第一步。
记录反归一化后的动作、机器人处理器输出、最终发送目标，以及关节位置反馈。
发送失败不能标记为已执行；总线发送成功也不能冒充每个舵机的目标回读确认。
用统一单调时钟对齐动作和视频，说明反馈是在发送前还是发送后采样。
追踪仅观察当前执行路径，不为调试额外调用模型生成一个新chunk替代真实动作。
如版本接口不同，先适配实际取动作的位置并用离线测试核对来源。

六、分析和验收
编写 scripts/analyze_trial.py，输出夹爪目标/反馈时间线，
定位张开候选事件，提取事件前后约两秒的视频，保留轮号与chunk/step。
候选事件不自动判为失败，结合视频区分正常放置松爪和提前释放。
提供n_action_steps=100与10的单变量对照配置，保持checkpoint、chunk_size和频率不变，
同时记录新chunk耗时、发送间隔和停顿；更换checkpoint是另一次独立对照。

先用FakeBackend和模拟相机验证完整Enter循环、忙时回车、120秒结束、十轮上限、
每轮清空队列、预览关闭不停止控制、部分连接失败后的清理和所有轮次视频保存。
--check 仅展开配置，不连接设备；真实运行命令与离线检查必须使用同一套解析。
先交付代码、配置、测试结果、操作步骤和完整实机命令，审核后先做单轮再做多轮。
```
